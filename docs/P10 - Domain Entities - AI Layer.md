## 1. Entities in the AI Layer

### 1.1 AIConversation (`AIS_CONVERSATION` / `ACV`)

**Purpose**

* Represent a logical copilot session (Employee Copilot, Manager Copilot, HR-assist, appraisal assist).
* Anchor all messages, context and metadata used for AI interactions.
* Enforce tenant + user/role scoping at the session level.

**Key attributes (business-level)**

* Conversation ID
* Tenant reference (→ Tenant)
* User reference (→ SYS_USER / Employee)
* Conversation type

  * e.g. `EMPLOYEE_COPILOT`, `MANAGER_COPILOT`, `HR_REQUEST_ASSIST`, `APPRAISAL_SUMMARIZER`, `COACHING_ASSISTANT`
* Entry surface

  * e.g. ESS, MSS, HR Requests UI, Appraisal screen
* Subject entity type (optional)

  * e.g. `PERF_APPRAISAL`, `HR_REQUEST`
* Subject entity ID (optional)
* Started at / ended at timestamps
* Status (Active / Closed)

**Multi-tenant?**

* **Yes** – conversation is strictly scoped to one tenant.

---

### 1.2 AIMessage (`AIS_MESSAGE` / `AMS`)

**Purpose**

* Store individual turns in a conversation (user prompts, AI replies, system notices).
* Capture content, role (user vs AI), and transparency metadata (sources, labels).

**Key attributes**

* Message ID
* Tenant reference (→ Tenant) (through conversation or explicit)
* Conversation reference (→ AIConversation)
* Sender type (User / AI / System – code)
* Sender role context (Employee / Manager / HR / Exec – code)
* Message content (text)
* Content type/format (plain text, rich text snippet)
* Is AI suggestion? (Y/N)

  * Used to ensure all AI-generated messages are clearly labelled as “suggestions/drafts”.
* Underlying data sources (summary / JSON: which entities & fields were used)
* Created at timestamp

**Multi-tenant?**

* **Yes** (via tenant-scoped conversation).

---

### 1.3 HRRequest (`AIS_HR_REQUEST` / `AHR`)

**Purpose**

* Represent a generic HR query logged by an employee or manager (PW-AI-10).
* Provide a work item that AI can help classify and draft responses for.

**Key attributes**

* HR request ID
* Tenant reference (→ Tenant)
* Requester reference (→ Employee or User)
* Requester role (Employee / Manager – code)
* Subject / short title
* Request body/details (text)
* Channel/source (ESS / MSS / email-import / other)
* Status (New / Triaging / InProgress / Closed – code)
* Assigned HR queue or specific assignee (optional)
* Created at / updated at timestamps

**Multi-tenant?**

* **Yes**

---

### 1.4 HRRequestClassification (`AIS_HR_REQUEST_CLASSIFICATION` / `AHC`)

**Purpose**

* Store AI-generated classification and routing suggestions for a specific HR request (PW-AI-11).
* Track confidence and whether the suggestion was accepted by HR.

**Key attributes**

* Classification ID
* Tenant reference (→ Tenant)
* HR request reference (→ HRRequest)
* Predicted request type (e.g. leave, contract, payroll, wellness, policy_question – code)
* Suggested assignee or HR queue
* Confidence score
* Classification model / version used
* Suggested at timestamp
* Accepted flag (Y/N)
* Accepted by (HR user, optional)
* Accepted at timestamp

**Multi-tenant?**

* **Yes**

---

### 1.5 AIFeedback (`AIS_AI_FEEDBACK` / `AFB`)

**Purpose**

* Capture user reactions to AI outputs: Accept/Edit/Reject and helpfulness rating (PW-AI-13).
* Provide a governance and tuning signal across copilots, summarizer and HR assistant.

**Key attributes**

* AI feedback ID
* Tenant reference (→ Tenant)
* User reference (→ SYS_USER / Employee)
* Target type

  * e.g. `COPILOT_REPLY`, `APPRAISAL_SUMMARY`, `COACHING_SUGGESTION`, `HR_REQUEST_REPLY`
* Target reference

  * Usually → AIMessage or → HRRequest (depending on where the AI output is stored)
* Action taken

  * Accept / Edit / Reject – code
* Helpfulness rating

  * e.g. Helpful / NotHelpful / Neutral – code
* Optional edited text snapshot (if user edited the suggestion)
* Free-text comment (why it was wrong/unhelpful)
* Created at timestamp

**Multi-tenant?**

* **Yes**

---

### 1.6 (Conceptual) AIOutputSlot

> This is **conceptual**, not necessarily a separate table – the “slot” is often a field in another entity.

**Purpose**

* Represent a place where AI writes a suggestion that must be reviewed before becoming “official”:

  * Appraisal overall summary (PW-AI-05–07)
  * Coaching phrasing suggestions (PW-AI-08–09)
  * Suggested first response to an HR request (PW-AI-12)

**Key attributes (concept-level)**

* Owning entity reference (e.g. PerfAppraisal, HRRequest)
* Output type (AppraisalSummary / CoachingSuggestion / HRReply)
* Draft text generated by AI
* Status (Draft / Accepted / Edited / Rejected)
* Last generated at / last action at

**Multi-tenant?**

* In practice, **lives inside the owning domain entity**, which is tenant-scoped.
* The AI Layer interacts with these fields but does not own the tables.

## 2. Relationships (AI Layer)

Using `A (1) -- (many) B` to mean “one A to many B”.

### Core AI conversation model

1. **Tenant – AIConversation**
   `Tenant (1) -- (many) AIConversation`

   * All conversations are scoped to a tenant (PW-AI-14, PW-AI-15).

2. **User/Employee – AIConversation**
   `User/Employee (1) -- (many) AIConversation`

   * One user can have multiple sessions with Employee Copilot, Manager Copilot, etc.

3. **AIConversation – AIMessage**
   `AIConversation (1) -- (many) AIMessage`

   * Each conversation has multiple messages; messages inherit tenant + context.

4. **AIMessage – AIFeedback**
   `AIMessage (1) -- (0..many) AIFeedback`

   * A single AI message may receive multiple feedback events (e.g. initial Reject, then Accept after edit).

### HR request classification

5. **Tenant – HRRequest**
   `Tenant (1) -- (many) HRRequest`

6. **User/Employee – HRRequest**
   `User/Employee (1) -- (many) HRRequest`

   * Requester.

7. **HRRequest – HRRequestClassification**
   `HRRequest (1) -- (many) HRRequestClassification`

   * Each request may be classified more than once (re-runs or different models). One is “current/accepted”.

8. **HRRequest – AIConversation (optional)**
   `HRRequest (0..1) -- (0..many) AIConversation`

   * Some HR Requests may be created via a copilot chat; you can store a loose association.

9. **HRRequest – AIOutputSlot / AIMessage**

   * HR-request suggested reply is often an AIMessage in a related conversation, or a field on HRRequest:

     * `HRRequest` holds latest “AI draft reply”.
     * `AIFeedback` targets that draft.

### Performance-related AI

10. **PerfAppraisal – AIConversation (optional)**
    `PerfAppraisal (0..1) -- (0..many) AIConversation`

    * Appraisal summarizer and coaching hints may use a dedicated conversation or reuse a shared one.

11. **PerfAppraisal – AIOutputSlot** (conceptual)

    * One appraisal can have a single “overall summary” slot which AI writes to.
    * `AIFeedback` records whether that summary was accepted/edited/rejected.

### Governance & scoping

12. **Tenant – AIFeedback**
    `Tenant (1) -- (many) AIFeedback`

    * All feedback is tenant-scoped for privacy and analytics.

13. **User – AIFeedback**
    `User/Employee (1) -- (many) AIFeedback`

    * Trace who accepted/rejected/flagged each AI output.

> All AI entities are designed to obey:
>
> * **Tenant isolation:** no cross-tenant data in prompts or stored context.
> * **Role-based visibility:** conversation + HR Request queries must respect user’s permissions.

## 3. Cross-domain / Overlap Flags

* **Employee / User (`PID_EMPLOYEE`, `SYS_USER`)**

  * Owned by People/Core/System domains. AI entities reference them for scoping and auditing.

* **PerfAppraisal (`PRF_PERF_APPRAISAL`)**

  * Owned by Performance domain. AI summarizer and coaching hints read its content and write draft summaries/phrases into fields on PerfAppraisal.

* **CheckIn (`PRF_CHECKIN`), Leave (`LEA_*`), RecoveryIndex (`LEA_RECOVERY_INDEX`), Gamification**

  * Owned by other domains. AI copilots (especially Manager Insight Copilot) read them via services/API, and may reference their use in `AIMessage.underlyingSources`.

* **HRRequest vs “Ticketing” domain**

  * For now, HRRequest is owned by the AI/Conversation domain (because its primary interaction is AI-assisted classification and replying). If a richer HR case management module is added later, ownership might move there.

* **AIOutputSlot**

  * Typically **not** a first-class table; represented as fields on PerfAppraisal or HRRequest. Still important conceptually for domain boundaries and governance.
